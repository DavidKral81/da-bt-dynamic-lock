================================================================
  DA BT DYNAMIC LOCK
  Locks your computer when you walk away with your phone.
================================================================

A replacement for the built-in "Dynamic Lock" in Windows, which
is unreliable and gives you nothing to set up.

It comes in two parts:
  1. app on the computer  - listens and locks
  2. app on the phone     - broadcasts a bluetooth signal

For a phone you need both. A phone broadcasts almost nothing on
its own, so the computer would have nothing to listen to.

You can watch a different device instead, with nothing installed
on it - but only one that keeps broadcasting on Bluetooth LE by
itself, such as a beacon, a fitness band or a watch. Nothing is
ever paired: the computer only listens to what is in the air.
Classic bluetooth accessories are therefore never heard at all,
and most accessories go quiet as soon as they connect to
something.

The app can only LOCK. It cannot unlock - Windows does not allow
that to third-party programs. When you come back, sign in with
your PIN or fingerprint.

----------------------------------------------------------------
  1. INSTALLATION
----------------------------------------------------------------

Download  DaBtDynamicLock.exe  from the GitHub release and run it.
It asks for administrator rights on its own and offers to install;
it is the same file that then gets installed:
  https://github.com/DavidKral81/da-bt-dynamic-lock/releases/latest

It offers three options:
  - add a shortcut to the Start menu
  - add a shortcut to the desktop
  - start automatically after sign-in

Where things are stored:

  program                   C:\Program Files\Da BT Dynamic Lock
  settings, log, history    %APPDATA%\Da BT Dynamic Lock

The program is shared by everyone on the computer; the settings
belong to each user separately. Automatic start applies only to
the user who turned it on.

UNINSTALLING

Settings → Apps → Installed apps → Da BT Dynamic Lock.
This removes the program, the shortcuts and the scheduled task.
By default it does NOT delete your settings and history - there
is a separate checkbox for that, so reinstalling keeps your data.



----------------------------------------------------------------
  2. QUICK START
----------------------------------------------------------------

ON THE PHONE (Android)

  1. Download  DaBTDynamicLock.apk  from the same release onto the
     phone and open it. Allow installation from this source.
     (The APK is not bundled with the installer - the program window
     has a "Download the phone app" link that takes you there.)
  2. Start the app and tap "Turn broadcasting on".
     Allow the "Nearby devices" and "Notifications" permissions.
  3. Settings → Apps → Da BT Dynamic Lock:
       - battery: unrestricted
       - autostart: on
     (on Xiaomi phones autostart lives in the Security app)

  You are done when the app shows a green "Broadcasting".

ON THE COMPUTER (Windows)

  4. Start Da BT Dynamic Lock. It has no window of its own; it
     runs as an icon near the clock, grey until a phone is chosen.
  5. Click the icon. The window opens → pick "Phone and Wi-Fi" on
     the left → choose your phone under "Which device to watch".
     (You can also right-click the icon → "Which device to watch".)

  Done once the icon is green. Walk away with the phone and the
  computer locks within 45 seconds.

----------------------------------------------------------------
  5. SIGNAL CHART
----------------------------------------------------------------

The "Signal monitor" page in the app window. The range is chosen
with the buttons in the top right: 2m, 5m, 15m, 1h, 8h, 1D, and the
legend is right under the chart. The horizontal axis shows the time
of day (with seconds on the 2m range), the vertical one the signal
strength in dBm. In a wide or maximised window the chart takes the
whole width. The history survives both an
app restart and a computer restart. Time when the app was not
running is marked separately and does not count as a lost signal.

What it is good for: it tells two different problems apart.

  Curve low                 weak signal - distance, pocket, body
  Curve high but full of    something else is interfering with
  gaps                      reception - a bluetooth mouse,
                            keyboard, Wi-Fi
  Grey dots                 the signal did arrive, but it is below
                            the sensitivity threshold, so it does
                            not count



----------------------------------------------------------------
  6. SENSITIVITY (RANGE)
----------------------------------------------------------------

This decides how weak a signal still counts as "you are at the
desk".

  Phone inaudible   locks only when the signal disappears (default)
  -100 to -85       longer range, locks later
  -80 to -60        shorter range, locks sooner

Measured at a desk: phone in a pocket -81 to -83 dBm, phone on
the desk -73 dBm. So -80 and above is stronger than a normal
pocket signal and will start locking even while you sit still.

Distance in metres CANNOT be set. The difference between "at the
desk" and "three metres away" is 2 dB, which is less than the
natural fluctuation of the signal. The whole thing works because
a phone in a pocket has a signal so weak that a wall cuts it off
completely - the edge of the room is also the edge of the signal.



----------------------------------------------------------------
  7. WARNING WHEN THE PHONE DISAPPEARS
----------------------------------------------------------------

After the chosen time without a signal (10 minutes by default)
a notification appears.

It covers a silent failure: when the phone stops broadcasting,
the computer locks once and then waits for the phone to show up
again. Until then it is NOT watching, but it looks as if it is.

There is one more check: before locking, the app
looks at whether the radio can hear anything else nearby at all
(a mouse, a TV, someone else's gadget). When it hears nothing
whatsoever, the silence belongs to the receiver rather than to the
phone - a scanner that has been running for hours sometimes stops
listening. The lock is then held off, the scanner is restarted and
the measurement starts again. This can happen at most twice in a
row, so watching still works in a genuinely quiet room. The log
line reads "Locking held off".



----------------------------------------------------------------
  8. STARTING AFTER SIGN-IN
----------------------------------------------------------------

Turn it on during installation, later in the icon menu ("Start
after signing in to Windows"), or in the window on the
"Application" page. All three do the same thing.

It creates a task in Task Scheduler with these settings:
  - starts 30 seconds after sign-in (bluetooth needs a moment)
  - repeats every 5 minutes, so watching comes back after a crash
  - no run-time limit (otherwise Windows would stop it after
    3 days)
  - runs on battery too

QUIT IT YOURSELF AND IT STAYS QUIT

The five-minute repeat is there for crashes, not to overrule you.
When you quit the application ("Quit the application" in the window
or in the menu), it makes a note of that and the repeating task
leaves it alone - it stays off until you next sign in (after
signing out, a restart or shutting the computer down), or until you
start it yourself. Sleep and locking the screen do not bring it
back.

To keep it off for good, use the "Start after signing in to
Windows" switch.

A crash leaves no such note behind, so watching returns within five
minutes on its own.

The app CANNOT run as a Windows service - services run in
a separate session with no access to the desktop, and cannot
lock the screen from there.

If the user is not allowed to create scheduled tasks, a fallback
is used: a shortcut in the Startup folder. That can only start
the app plainly, with no delay and no restart after a crash.
The log says which of the two was used.



----------------------------------------------------------------
  9. WHEN SOMETHING DOES NOT WORK
----------------------------------------------------------------

Start with  dyn_lock.log  in the data folder - it records when
the phone was seen, when it disappeared and why it locked.

  It locks while I am sitting at the desk
      Check that the phone app is broadcasting. If it is, then
      reception is poor - see the chart and the note below.

  It never locks
      "Phone seen for the first time" is missing from the log → pick the
      right phone in the settings (or in the icon menu).

  I cannot see the icon
      It is hidden under the arrow next to the clock.

      If Windows Explorer restarted in the meantime (the taskbar
      disappeared and came back), the app puts its icon back by
      itself and writes a line about it in the log.

  The log repeats "The tray icon could not be updated"
      Windows allows nothing into the notification area while the
      screen is locked, and briefly none while Explorer restarts.
      The app keeps trying and writes "The tray icon can be updated
      again." once it works. Watching is not affected.

  The app will not start twice
      That is correct - the second attempt only says it is
      already running.


WHY THE DEFAULT IS 45 SECONDS AND NOT 20

There is only one bluetooth radio in the computer and it has to
serve the mouse and the keyboard while listening for the phone.
Measured while sitting at the desk:

  phone on the desk, mouse on    177 signals/min, gaps up to 3 s
  phone in pocket, mouse off      84 signals/min, gaps up to 9 s
  phone in pocket, mouse on       20 signals/min, gaps up to 20 s

A pocket costs about 10 dB, and a bluetooth mouse eats roughly
three quarters of the signals that get through. Either one alone
is bearable; together they push reception below a usable level.

Three ways to make it faster:
  - move the mouse and keyboard to their own USB receivers
  - turn the Wi-Fi radio off (it shares the antenna with
    bluetooth)
  - carry the phone in the pocket closer to the computer



----------------------------------------------------------------
 10. SETTINGS IN THE FILE
----------------------------------------------------------------

The file  config.json  in the data folder
(%APPDATA%\Da BT Dynamic Lock). Most things are easier to change
in the app window; only these are edited in the file directly,
and the app has to be restarted afterwards:

  threshold_window_s   over how many seconds the signal is smoothed
  scanner_restart_s    how often to restart reception as a precaution
  silence_watchdog_s   after how long a silence to restart reception

The keys the app writes for itself can be read here too:

  window_w, window_h   the size the window was last closed at
  window_maximized     whether it was maximised

The remaining keys match the items in the window. A watched
device's MAC address can only be entered here (the "target" key),
because the list in the window offers named devices only.

----------------------------------------------------------------
 12. THE PHONE APP
----------------------------------------------------------------

It broadcasts a bluetooth signal carrying the phone's name.
Compared to general tools such as nRF Connect it can also:
  - start broadcasting after the phone is switched on
  - pick itself up as soon as bluetooth comes back (after
    aeroplane mode)

It has no internet permission, so it cannot send anything
anywhere. Its only permissions are: broadcast over bluetooth,
run in the foreground, start at boot, show notifications.

The language is changed in the top right corner: tapping the name of
the language opens a list (Čeština / English).

UPDATING WITHOUT A CABLE
At the bottom there is the version number and a "Download the
newest version" link. It opens the releases page in the browser -
download the .apk there and tap the downloaded file. It installs
over the existing app and the settings are kept. The first time,
the phone will ask you to allow installing from the browser.

The app itself asks nothing: the link only hands the address to
the browser, which is a different app. That is why no internet
permission is needed for it.

The broadcast interval (the time between two signals) can be set in
the app:
  Fast 100 ms      best response (default)
  Medium 250 ms    slightly slower response
  Saving 1 s       slowest, risk of false locking

Battery use is negligible with all three in practice - verified over
normal daily use. Broadcasting is a short signal, not a data transfer.

CAREFUL: the file  phone\signing-key-DO-NOT-DELETE.jks  must not
be deleted. Without it the phone app cannot be updated and would
have to be uninstalled and installed again. Details are in
signing-key-README.txt next to it.



----------------------------------------------------------------
 13. FOR DEVELOPERS
----------------------------------------------------------------

BUILDING AND TRYING IT OUT

    dotnet build app-2.0\App\App.csproj -c Release

The build can then be run like this (with no switch at all, a copy
outside the installed folder offers to install itself):

    DaBtDynamicLock.exe --dry-run      without actually locking; can
                                       run alongside the installed
                                       version
    DaBtDynamicLock.exe --self-check   works the window's controls
                                       and checks they are saved
    DaBtDynamicLock.exe --screenshot "<folder>"
                                       photographs the windows so the
                                       look can be checked

A test run keeps its data beside itself in a dry-run-data folder,
not in %APPDATA% - so the development and installed versions do not
share settings.

BUILDING THE INSTALLER

    powershell -ExecutionPolicy Bypass -File
        "...\Da BT Dynamic Lock\app-2.0\build-setup.ps1"

It produces a single DaBtDynamicLock.exe that is also the
installer, and checks it with the self-check. Nothing else is
bundled with it.

BUILDING THE PHONE APP

    powershell -ExecutionPolicy Bypass -File
        "...\Da BT Dynamic Lock\phone\build.ps1"

The source code is in  phone\src\ , and the finished APK appears
directly in  phone\ . It needs neither the internet nor Android
Studio, only the tools in the _android-build folder that sits next
to the project folder (one level up).
